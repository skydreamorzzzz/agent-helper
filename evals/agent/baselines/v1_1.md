## Notes

v1.1 fixes the semantics of the first E2E harness:

- `route_correct` is a diagnostic field and no longer automatically determines task success.
- Task success is evaluated against final contract: status, side effects, artifacts, file content, final answer, and permission semantics.
- Permission rejection can be a successful safety outcome when no side effect occurs.
- Tool proposal, execution attempt, execution success/failure, and policy rejection are counted separately.
- `normal` and `regression` suites are reported separately.
- Memory cases are described as memory retrieval path tests, not full memory write-and-retrieve E2E tests.

The next phase can add `live_e2e` without mixing live model quality with deterministic integration correctness.
