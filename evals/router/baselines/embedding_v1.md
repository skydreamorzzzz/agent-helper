# Router Embedding v1 Experiment

Dataset: `router-v1`

Status: observed development benchmark. The `router-v1/test` split has already been used for failure analysis and prototype discussion, so these numbers should not be treated as a strictly independent holdout score.

Split policy:

- `dev`: 42 examples for prototype and threshold iteration.
- `test`: 18 examples for stage-level validation.
- Test labels and split were not changed for this experiment.

Run context:

- Parent commit at run time: `639d1ef`
- Embedding provider: `hashing`
- Embedding model: `hashing-multilingual-v1`
- LLM model: `gemini-2.5-flash`
- Similarity threshold: `0.32`
- Margin threshold: `0.04`

## Prototype Strategy

`EmbeddingRouter` uses hand-written route prototypes for:

- `direct_answer`
- `single_tool`
- `web_lookup`
- `planned_task`
- `deep_research`
- `clarification`

The prototypes are short representative utterances in English and Chinese. They were designed from route definitions and dev-split failure categories, not copied from the test split and not generated by automatically using all dev examples as training data.

The first implementation uses a local dependency-free `HashingEmbedder`. It is a hashed lexical vector baseline, not a neural sentence embedding model. Its purpose is to establish the Router embedding interface, cache prototype vectors, and measure whether a cheap lexical-vector layer can outperform the previous Jaccard baseline before introducing heavier embedding dependencies.

## Mode Definitions

- `embedding_only`: historical alias for `hashing_only`; `ConstraintRouter -> HashingEmbedder-backed EmbeddingRouter -> direct_answer fallback`; no LLM.
- `embedding_hybrid`: historical alias for `hashing_hybrid`; `ConstraintRouter -> HashingEmbedder-backed EmbeddingRouter -> LLMRouter when embedding is uncertain`.

Existing v1 baselines:

- `lexical_baseline`: `ConstraintRouter + Jaccard SemanticRouter + fallback`.
- `current_hybrid`: current `RequestRouter + LLM`.

## Comparison

### lexical_baseline vs embedding_only

`embedding_only` improved test accuracy from `0.667` to `0.833` and macro-F1 from `0.621` to `0.813`, without LLM calls.

Representative fixes:

- `route_028`: `当前 NVIDIA 股价是多少？`
  - lexical: `direct_answer`
  - embedding: `web_lookup`
- `route_049`: `Compare the latest OpenAI, Anthropic, and Google model pricing and cite sources`
  - lexical: `web_lookup`
  - embedding: `deep_research`
- `route_060`: `分析一下`
  - lexical: `direct_answer`
  - embedding: `clarification`

### current_hybrid vs embedding_hybrid

`embedding_hybrid` reduced LLM escalation from `0.556` to `0.333` on test, but accuracy dropped from `0.833` to `0.778`.

This means the first cascade is cheaper but not yet a safe replacement for `current_hybrid`. A confident wrong embedding decision can block LLM correction.

## Representative Failures

- `route_040`: `Read draft.md, polish it, and save the revised version to final.md`
  - expected `planned_task`, predicted `single_tool`
  - Failure mode: hard file-tool constraint fires before embedding/LLM. This is a cascade ordering problem, not an embedding quality problem.
- `route_058`: `帮我把这个总结一下`
  - expected `clarification`, predicted `direct_answer`
  - Failure mode: vague reference still falls through when embedding is uncertain.
- `route_059`: `Summarize and save it somewhere`
  - expected `clarification`, predicted `planned_task`
  - Failure mode: embedding recognizes a multi-step save pattern but misses the missing destination/source requirement.
- `route_009`: `What happened in 2023-01-01?`
  - current hybrid expected `direct_answer`, predicted `web_lookup`
  - Failure mode: LLM still treats historical date questions as external lookup.

## Conclusion

The hashed lexical vector baseline is clearly better than the previous Jaccard semantic layer on the observed `router-v1/test` benchmark. However, the first cascade needs a stricter confidence or override policy before replacing `current_hybrid`, because incorrect confident routes can reduce accuracy even while saving LLM calls.

The next useful experiment is not a larger rewrite. It should focus on hard-constraint review and cascade policy:

- decide which hard constraints should become soft;
- allow LLM override for selected embedding decisions;
- test with a real multilingual sentence embedding provider behind the same `Embedder` protocol.
